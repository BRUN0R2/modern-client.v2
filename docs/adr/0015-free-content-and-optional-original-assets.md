# ADR-0015 — Free content by default; original assets optional and configured locally

- **Status:** Accepted. Supersedes [ADR-0009](0009-original-assets-from-the-user.md).
- **Date:** 2026-10-20

## Context

ADR-0009 made the Counter-Strike 1.6 installation **mandatory**: without it the game did not
start. This prevents testing the engine in CI without a copy of the game, keeps away
contributors who do not have the installation and couples the project to third-party
content. At the same time, those who own the game want to play with the original assets
without configuring anything by hand.

## Decision

### 1. Content sources, none of them mandatory

The game mounts its content from **sources**, layered by priority, in the VFS
([06 §2](../06-assets-and-resources.md#2-virtual-file-system-vfs)):

| Source (`kind`) | Origin | Redistributable |
|-----------------|--------|-----------------|
| `engine` | Embedded in the binary (console font, shaders, error screen) | Yes |
| `devContent` | Generated by code: grid textures, capsule player, simple weapons, synthesized sounds | Yes |
| `openContent` | Free community package, in its own repository | Yes |
| `goldsrcInstall` | The user's local CS 1.6 installation | **No** |
| `mod` | Mod packages | According to the mod's license |

The game works with `engine` + `devContent` (or `openContent`). The original assets are an
**optional** source, configured on the user's machine.

### 2. Ready-made profiles

| Profile | Sources | Use |
|---------|---------|-----|
| `classic` | `goldsrcInstall` (`cstrike` and `valve`) | Original experience: CS 1.6 visuals, sounds, HUD and maps |
| `open` | `openContent` | The game without any Valve asset |
| `dev` | `devContent` | Engine development and CI |
| `custom` | Explicit list | Custom combinations |

In the `classic` profile, a missing essential file is a **typed error** with the list of
what is missing. There is no silent filling with other content.

### 3. Automatic detection and local configuration

- At the first start (and with `content_scan`) the engine looks for the installation in the
  system's Steam libraries (Windows and Linux) and validates it against the list of
  essential files in `data/content/goldsrcCstrike.toml`.
- If it finds one, the wizard asks once whether the user wants to use the original assets
  and saves the choice (the `classic` profile).
- The configuration lives **in the user's profile, outside the repository**:
  `%APPDATA%\Modern-Client.v2\content.toml` (Windows) and
  `~/.config/modern-client.v2/content.toml` (Linux). The repository ships only
  `content.example.toml`.
- It can also be configured from the command line (`--content classic`,
  `-basedir <path>`) and from the console (`content_list`, `content_scan`,
  `content_add <path>`, `content_profile <profile>`).

### 4. Non-redistributable content never leaves the machine

- Every served resource carries the source it came from. The server's download service
  **refuses** to send files from non-redistributable sources (`goldsrcInstall`).
- A server that depends on a non-redistributable source declares it (`requires`) in the A2S
  rules and in the handshake. The client needs to have it locally, verified by hash. If it
  does not, the connection is refused with a typed reason and instructions on how to
  configure it.
- This way, neither the project nor the servers distribute Valve content, not even
  indirectly.

## Alternatives considered

| Alternative | Why not |
|-------------|---------|
| Keep the original installation mandatory (ADR-0009) | Prevents CI and contributions without the game and couples the project to third-party content |
| Free content only | Would lose the original experience for those who own the game |
| Distribute the original assets | Copyright infringement |
| Complete the `classic` profile with free content when a file is missing | Silent fallback: mixes visuals and hides a broken installation |

## Consequences

- ✅ The engine runs and is tested end to end without any external asset.
- ✅ Those who own CS 1.6 play with the original assets with almost no configuration.
- ✅ The gameplay is the same in every profile: parity lives in the code and the data. Only
  the presentation changes.
- ⚠️ `openContent` is a long-term art project. The assets have to be original or
  CC0/CC-BY, without imitating Valve's visual identity (own maps, no replicas).
- ⚠️ Free maps need a free toolchain (the TrenchBroom editor + the project's `.nxmap`
  compiler), because the classic BSP30 compilers derive from Valve's SDK.
