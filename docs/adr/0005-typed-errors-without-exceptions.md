# ADR-0005 — Typed errors with `std::expected` and contracts, without exceptions

- **Status:** Accepted
- **Date:** 2026-10-20

## Context

The request is "fully typed errors". Exceptions hide failure paths from signatures, have an
unpredictable cost and are hard to use with parallel jobs and plugin boundaries. Generic
error codes (`bool`, `-1`) lose information.

## Decision

- **Expected** failures: `nx::Result<T, E>` = `std::expected<T, nx::Failure<E>>`, where `E`
  is the module's `enum class` and `Failure` carries context, `source_location` and a chained
  cause ([02 §6](../02-coding-standards.md#6-typed-errors)).
- **Invariant violations**: C++26 contracts (`pre`, `post`, `contract_assert`) with
  per-module semantics.
- **Unrecoverable**: `nx::fatal` with a crash report.
- Compilation **without exceptions and without RTTI** in the project's own modules. Libraries
  that throw exceptions stay isolated behind boundaries that convert to `Result`.
- Errors exposed to plugins become Rook `error enum`s generated by reflection.

## Alternatives considered

| Alternative | Why not |
|-------------|---------|
| Exceptions | Failures invisible in signatures, cost and complexity with jobs |
| `std::error_code` | Dynamic, weakly typed category, without rich context |
| Propagation macros (`TRY`) | Not portable (they depend on *statement expressions*) and hide the flow |

## Consequences

- ✅ Every failure path appears in the signature and is checked by the compiler
  (`[[nodiscard]]`).
- ✅ The same philosophy in C++ and in Rook.
- ⚠️ Slightly more verbose propagation. Mitigation: monadic operations and small functions.
