# 06 — Assets and resources

> Decision on content sources and original assets in [ADR-0015](adr/0015-free-content-and-optional-original-assets.md).

## 1. Goals

- **Work without any Valve asset** (free content and content generated by code) and, when the
  user owns CS 1.6, load the original files **directly** from the local installation
  (BSP, MDL, WAD, SPR, WAV, configs), with no manual conversion and almost no configuration.
- **End precache:** unlimited resources, registered at any time, with incremental download
  to clients.
- **Asynchronous** loading in jobs, without stalling the frame.
- Modern formats for mods (glTF, KTX2, PNG, OGG/Opus, FLAC).
- Security: no arbitrary path and no unverified file coming from the network.

## 2. Virtual file system (VFS)

### 2.1 Mount points

Search order (highest priority first), equivalent to the GoldSrc *search path*. Only
`engine` is always present. The game sources come from the active content profile
([§2.4](#24-content-sources-and-profiles)):

| Priority | Mount | Content | Redistributable |
|----------|-------|---------|-----------------|
| 1 | `mods/<mod>/` (in dependency order) | Assets of enabled mods | Depends on the mod |
| 2 | `downloads/` | Cache of downloaded resources (content-addressed) | Yes (only receives redistributable content) |
| 3 | `addons/cstrike/` | The user's local custom content (`cstrike_addon`) | No (it belongs to the user) |
| 4 | The profile's game source: `<install>/cstrike/` + the base files Counter-Strike 1.6 loads from `<install>/valve/` (`classic`), `openContent` (`open`) or `devContent` (`dev`) | Game content | `goldsrcInstall`: **no**. The others: yes |
| 5 | `engine/` (embedded) | Engine minimum: console font, fallback shaders, error screen | Yes |

Today the VFS (`nx::assets::Vfs`) mounts directories, in the order it is given. The content
sources and profiles that decide which mounts exist, `.nxpak` packages ([§8](#8-packages)) and
the embedded `engine/` mount are planned (M2, [TODO](../TODO.md)).

### 2.2 Path rules

- Logical paths (`nx::assets::VfsPath`) are relative, use `/` as the separator and are looked
  up **case-insensitively** for ASCII letters (as on Windows, where the maps were made); other
  bytes compare exactly. A path keeps the spelling it was written with, for diagnostics.
- **Forbidden:** an empty path, empty components (`a//b`, a trailing `/`), `.` and `..`
  components, absolute paths, `\`, `:` (drive letters and NTFS streams), control bytes, more
  than `kMaxResourcePathBytes` (1024 bytes) and extensions outside `kAllowedExtensions`: those
  of the formats of [§3](#3-supported-formats). A violation yields `VfsError::InvalidPath`,
  whose detail names the rule; text over the ceiling is reported by its size, never repeated.
- Creating the VFS indexes the regular files of every mount (symbolic links to directories are
  not followed: they can lead into a cycle). Lookup is O(1), by hash of the lowercased path, and
  never hands the caller's text to the operating system. Files whose relative paths are not
  valid logical paths (another extension, a `:` in a name) are not content and stay out of the
  index.
- Two files of one mount whose paths differ only in case (possible on Linux) would make a path
  ambiguous: creating the VFS fails with `VfsError::MountFailed`, naming both, unless a higher
  mount has that path. The VFS never picks one silently.
- The VFS is immutable, so any thread reads through it. Another set of mounts (a content
  profile, an enabled mod) is a new VFS. A *watch* that refreshes the index in development
  comes with hot reload ([§4.4](#44-hot-reload-development)).

### 2.3 Locating the original installation (optional)

The CS 1.6 installation is **optional** ([ADR-0015](adr/0015-free-content-and-optional-original-assets.md)). When the profile is `classic`, it
is searched for in this order:

1. Explicit option: `-basedir <path>` on the command line or `goldsrcInstall.path` in
   `content.toml`.
2. Steam on Windows: the Steam path in the registry (`HKCU\Software\Valve\Steam`, value
   `SteamPath`), plus the libraries listed in `steamapps/libraryfolders.vdf`.
3. Steam on Linux: `~/.steam/steam`, `~/.local/share/Steam` and the Flatpak installation
   (`~/.var/app/com.valvesoftware.Steam/.local/share/Steam`), plus `libraryfolders.vdf`.
4. In each library: the CS 1.6 manifest (`steamapps/appmanifest_10.acf`, Steam app 10) and
   the `steamapps/common/Half-Life` folder, with `cstrike/` and `valve/`. Steam names the
   folder after Half-Life, the base game of CS 1.6; only CS 1.6's files are read from it
   ([ADR-0017](adr/0017-counter-strike-only.md)).

`nx::platform::steamFolders` finds the Steam folders of steps 2 and 3 (each once: `~/.steam/steam`
is usually a link to `~/.local/share/Steam`). `nx::assets::detectGoldsrcInstall` reads each
`libraryfolders.vdf` (Valve KeyValues, both layouts Steam has written) and takes, in library
order, the first installation that passes validation. An installation that exists but fails
validation is reported with its failure, never skipped in silence; with none, the result is
`ContentError::InstallNotFound`. The app number and the folder name come from
`data/content/goldsrcCstrike.toml` (`steamAppId`, `steamInstallFolder`).

**Validation** (`nx::assets::GoldsrcInstall::open`) checks the installation against
`data/content/goldsrcCstrike.toml`: its mounts (`cstrike`, then `valve`) and its essential
files, written `<mount>/<logical path>` (`cstrike/liblist.gam`, `valve/halflife.wad`, player
models, `cstrike/sprites/hud.txt`, official maps), each found in the mount it names whatever
the case of its letters. A missing mount yields `ContentError::InstallNotFound`; missing files
yield `ContentError::MissingEssentialFiles` with the full list.

### 2.4 Content sources and profiles

| Profile | Mounted sources | When |
|---------|-----------------|------|
| `classic` | `goldsrcInstall` (`cstrike` and `valve`) | Players who own CS 1.6 and want the original experience |
| `open` | `openContent` | The game without any Valve asset |
| `dev` | `devContent` | Engine development and CI |
| `custom` | Explicit list in `content.toml` | Custom combinations |

- `devContent` is **generated by code** (grid textures, capsule player, simple weapons,
  synthesized sounds) and lets the engine run end to end without any external file.
- `openContent` is the community's free package (`.nxpak`), with original or CC0/CC-BY
  assets.
- In the `classic` profile, a missing essential file is an error; it is **not** filled in
  from another source (no silent fallback). `asset_stats` shows which source each resource
  came from.
- Without configuration, the initial profile is decided by the first-start wizard
  ([§2.5](#25-local-configuration)). Without any package, the game opens with `dev`.

### 2.5 Local configuration

- **First start:** if detection finds a valid installation, the wizard asks once:
  *"Counter-Strike 1.6 found at <path>. Use the original assets?"*. The answer is written
  to `content.toml` (profile `classic` or `open`/`dev`).
- **Where `content.toml` lives:** in the user profile, outside the repository:
  `%APPDATA%\Modern-Client.v2\content.toml` (Windows) and
  `~/.config/modern-client.v2/content.toml` (Linux). For development, a `content.toml` in
  the working directory takes precedence (and is ignored by git). The repository ships the
  commented template `content.example.toml`.
- **Command line:** `--content <profile>`, `-basedir <path>`,
  `--content-config <file>`.
- **Console:** `content_list` (mounted sources, order and origin), `content_scan` (reruns
  detection), `content_add <path>` (registers an installation and validates it),
  `content_profile <profile>` (switches the profile; takes effect on the next map load).

## 3. Supported formats

### 3.1 GoldSrc (direct reading)

| Format | Use | Notes |
|--------|-----|-------|
| BSP v30 | Maps | Geometry lumps, colored lightmaps, PVS, clipnode hulls, entity lump, embedded textures |
| WAD3 | Textures | `halflife.wad`, `cstrike.wad`, `decals.wad`, `tempdecal.wad` (sprays), WADs referenced by the `wad` key of `worldspawn` |
| MDL v10 | Studio models | Bones, sequences, *blends*, hitboxes, attachments, events, textures (including `*T.mdl`) and sequence groups (`*01.mdl`) |
| SPR v2 | Sprites | HUD, effects, smoke, crosshair |
| WAV (8/16-bit PCM) | Sounds | *Cue* points for looping. Original rates (11/22/44 kHz) |
| `sentences.txt` | Radio phrases and speech | Word composition with pitch/volume parameters |
| `materials.txt` | Material type per texture | Footstep sounds and bullet penetration |
| `titles.txt` | In-game text messages | Localizable |
| `hud.txt` and `sprites/*.txt` | HUD sprite layout | Per resolution |
| `*.res` | Per-map resource list | Become manifest dependencies ([§6](#6-end-of-precache-resource-registry)) |
| `*_detail.txt` | Per-map detail textures | Optional support, as in CS 1.6 |
| `overviews/*.txt` + BMP image | Spectator overview map | |
| `gfx/env/*.tga` | Sky box | Six faces per `skyname` of `worldspawn` |
| `liblist.gam`, `*.cfg`, `mapcycle.txt`, `motd.txt` | Configuration | See [09](09-dedicated-server.md) and [12](12-ui-hud-and-console.md) |

### 3.2 Modern (for mods)

| Format | Use |
|--------|-----|
| glTF 2.0 / GLB | Models with skinning of up to 4 influences, animations, materials |
| KTX2 (Basis Universal) | Compressed textures, transcoded to the GPU format |
| PNG, TGA | Textures and HUD |
| `.nxspr` | **Modern sprite**: TOML descriptor + RGBA PNG/KTX2 frames, any resolution, mipmaps, per-frame timing |
| OGG Vorbis, Opus, FLAC | Audio (music and long effects streamed) |
| TTF/OTF | UI fonts |
| TOML | Data, configs, manifests |

### 3.3 Maps without BSP limits (future)

BSP v30 has format limits (16-bit indices in clipnodes and marksurfaces, among others).
Support for large maps comes from an in-house extended format (`.nxmap`), imported from the
existing compile tools. See [TODO](../TODO.md).

### 3.4 Removed content limits

The original files are still read as they are, but the **internal representation** of
models, sprites and textures has no fixed-size tables. That way, new content (glTF,
`.nxspr`, KTX2) and mods do not inherit the GoldSrc ceilings.

| Limit in the original | Problem for mods | In Modern-Client.v2 |
|-----------------------|------------------|---------------------|
| **Attachments**: the client only uses 4 per entity | Weapons with muzzle, shell, sight, flashlight and extra effects do not fit | Unlimited count, access by **name** or index (`getAttachment(entity, "muzzle")`) |
| **Body groups**: every combination of submodels packed into a single `body`, transmitted with few bits | *Weapon packs* and models with many parts break in multiplayer | Selection **per body part**, replicated separately (varint per part). A legacy 64-bit `body` only for compatibility |
| **Sprites**: paletted SPR (256 colors), binary or additive alpha, limited size | Low-quality, aliased HUD and effects | `.nxspr` with true RGBA, smooth alpha, any resolution the GPU supports, mipmaps, compression and per-DPI variants |
| Paletted 8-bit **model and WAD textures** | Poor textures, no real alpha | RGBA textures and GPU compression (KTX2) in glTF models and high-resolution texture packs |
| Limited **bones per model** (128) and **vertices per submodel** | Detailed models impossible | Bone palette in a storage buffer (no format ceiling) and 32-bit vertex indices |
| **Bone controllers** (4 + mouth) and **blends** (2) per entity | Limited procedural animation | Dynamic per-entity lists |
| **Skins** and **sequences** with format ceilings | Limited variations | Dynamic lists |
| **WAD texture names** of up to 15 characters | Cryptic names | No limit in the new formats (the original WAD keeps its own limit) |
| **Resource paths** of up to 64 characters | Shallow folder structures | No format limit. A named, high safety ceiling (`kMaxResourcePathBytes`) |

Rules:

- When a real technical limit exists (the GPU's maximum texture size, memory), it is
  **queried at runtime**. Content above it yields a typed error (`AssetError::ExceedsDeviceLimit`)
  with the value and the limit, never a silent cut.
- The network replicates attachments, body parts, controllers and blends with **typed
  lists** (varint), never fixed-width fields inherited from the original
  ([08 §6.1](08-networking.md#61-snapshots)).
- `nxbake` produces reports of the imported content (bones, vertices, texture size), so
  authors see the cost of what they are creating.

## 4. Asset system

### 4.1 Handles and states

```cpp
auto model = assets.load<nx::assets::StudioModel>("models/player/gign/gign.mdl");
// model : nx::Result<AssetHandle<StudioModel>, AssetError>; the path is validated synchronously.

switch (assets.state(*model)) {
    case AssetState::Loading: /* ... */ break;
    case AssetState::Ready:   /* ... */ break;
    case AssetState::Failed:  /* assets.failure(*model) yields the typed cause */ break;
}
```

- `AssetHandle<T>` is typed and generational. There is no untyped "generic" handle in the
  public API.
- `load` **validates the path and existence** synchronously (a VFS index query) and
  schedules the load. A nonexistent file yields an immediate error, not a broken handle.
- Decoding errors (a corrupted file) take the asset to the `Failed` state, with a queryable
  `nx::Failure<AssetError>` and a diagnostic event.

### 4.2 Loading pipeline

```mermaid
flowchart LR
    A[Request] --> B[Async I/O<br/>I/O thread]
    B --> C[Decoding<br/>Low/Normal job]
    C --> D[Dependencies<br/>textures, sequences]
    D --> E[GPU upload<br/>staging ring]
    E --> F[Ready]
```

- Assets with dependencies (model → textures → sequence groups) become `Ready` only when
  all their dependencies are ready.
- Priority rises automatically when an asset is needed in the current frame (e.g. a player
  model that just entered the PVS).
- Reference counting with deferred release. Memory budgets per category
  (`asset_budget_textures`, `asset_budget_sounds`) with LRU eviction of unreferenced
  assets.

### 4.3 Baking

- `nxbake` converts authoring formats into optimized runtime formats (textures with
  mipmaps and GPU compression, reordered meshes, audio resampled when needed).
- The cache lives in `cache/baked/<content-hash>-<importer-version>`. If the original or
  the importer changes, the cache is invalidated.
- GoldSrc assets can be read without baking (the default path for the original content).
  Baking is an optimization.

### 4.4 Hot reload (development)

- The VFS watches the mounts. A changed file makes the asset reload and its dependents get
  notified.
- Works for textures, models, sounds, shaders, game data (TOML) and Rook plugins.

## 5. Maps

Loading a map involves:

1. Reading the BSP and validating the lumps.
2. Building the **collision hulls** (clipnodes) and the render BSP tree.
3. Resolving textures: embedded in the BSP or in the WADs listed in `worldspawn`.
   A missing texture yields a load error with the texture name and the list of WADs tried.
4. Packing lightmaps into atlases.
5. Reading the entity lump and instantiating prefabs ([03 §11](03-ecs.md#11-prefabs-and-map-entities)).
6. Reading the map's `.res` and building the resource manifest.
7. Loading the optional parts: detail textures, overview and navigation mesh (bots).

Loading runs as a job graph. The goal is to load `de_dust2` in under 1 second from a warm
cache.

## 6. End of precache: resource registry

### 6.1 The original problem

In GoldSrc, every model, sound and generic resource had to be declared in the *precache*,
inside fixed-size tables (around 512 entries per type) and only at map initialization. This
forced mods to cut content.

### 6.2 New model

| Aspect | GoldSrc | Modern-Client.v2 |
|--------|---------|------------------|
| Count | Fixed ceiling per type | No ceiling (32-bit IDs per session) |
| Registration time | Only in the map precache | Any time: on plugin load, on map change or during the match |
| Network identification | Table index | `ResourceId` (varint) plus content hash |
| Delivery to the client | Download before joining | **Required** ones before joining. **On demand** during the match |
| Integrity | Optional (`mp_consistency`) | Content hash always verified |

### 6.3 How it works

- The server keeps a **manifest** `ResourceId → {logical path, type, hash, size,
  policy}`.
- On connecting, the client receives the manifest and downloads the resources with the
  `Required` policy (declared on plugin load and in the map's `.res`).
- Resources registered during the match are announced by the reliable message
  `ResourceAdded`. The client resolves them in the background: it uses the local cache if
  the hash matches, or downloads them if it does not have them.
- Game logic on the server **never** depends on the client having already loaded a
  resource.

### 6.4 Resource not yet available on the client

| Type | Explicit behavior (always recorded in diagnostics) |
|------|----------------------------------------------------|
| Player model | Uses the **team's default model** until it loads. Never invisible, for competitive fairness |
| Other models | Hidden until loaded, with a counter in `asset_stats` |
| Sound | Does not play until loaded. Sounds marked `Critical` (footsteps, gunshots) are `Required` by rule |
| HUD sprite | The element is not drawn and the plugin receives a `ResourceUnavailable` event |

### 6.5 File consistency

- Resources may require **exact consistency** (`consistency = "exact"`): the client proves
  that the local file has the expected hash, like the original `force_unmodified`. It is
  useful for player models and crosshair sprites.
- An inconsistency causes a disconnect with a typed reason
  (`DisconnectReason::InconsistentFile`) and the file name.

## 7. Resource downloads

| Channel | When | Details |
|---------|------|---------|
| Built-in (UDP, on the reliable channel) | Default | Fragmented, rate-limited by `sv_download_rate`, without hurting game traffic |
| Fast HTTP(S) | If `sv_downloadurl` is set | Content-addressed URL (`<url>/<hash>`), CDN- and cache-friendly |

**Non-redistributable content never leaves the machine** ([ADR-0015](adr/0015-free-content-and-optional-original-assets.md)):

- Each entry of the resource manifest carries its origin source. The server **refuses** to
  send files that come from non-redistributable sources (`goldsrcInstall`,
  `addons/`): `ResourceError::NotRedistributable`.
- These resources reach the client as a **local requirement**, with a hash. The client
  looks for them in its own sources. If it does not find them, the connection is rejected
  with `RejectReason::MissingLocalContent{source, files}` and instructions on how to
  configure it.

Client security rules:

- The hash (BLAKE3) is verified **before** the file enters the VFS.
- An allow list of extensions per resource type. Executables and scripts outside the
  sandbox are rejected.
- A size ceiling per file and per server (`cl_download_max_size`,
  `cl_download_max_total`).
- `cl_allowdownload 0/1`. Client plugins follow their own rules
  ([13](13-mod-system.md#7-plugins-on-the-client)).
- The cache in `downloads/` is hash-addressed, shared between servers and cleaned by LRU
  (`cl_download_cache_size`).

## 8. Packages

- Mods and content are distributed as **`.nxpak`**: a container with an index,
  zstd-compressed entries, a per-entry hash and an optional signed manifest (Ed25519).
- The VFS mounts `.nxpak` without extracting it.
- `nxbake pack` produces reproducible packages (same input, same bytes).

## 9. Typed errors (summary)

| Enum | Examples |
|------|----------|
| `VfsError` | `InvalidPath`, `NotFound`, `MountFailed`, `ReadFailed` |
| `ContentError` | `InstallNotFound`, `MissingEssentialFiles{files}`, `UnknownProfile`, `SourceUnavailable{source}`, `ConfigInvalid{path, line}` |
| `AssetError` | `DecodeFailed`, `DependencyFailed`, `BudgetExceeded`, `UnsupportedFormat` |
| `BspError`, `MdlError`, `WadError`, `SprError`, `WavError` | Format errors with lump/offset |
| `ResourceError` | `UnknownResource`, `HashMismatch`, `DownloadRejected`, `TooLarge`, `ExtensionNotAllowed`, `NotRedistributable` |

## 10. Diagnostics

- `asset_stats`: assets per state, memory per category, load queue and downloads.
- `asset_list [filter]`, `asset_reload <path>`.
- `res_manifest`: the server's current manifest with policies and sizes.
